# Known issues

What is known to be wrong or missing and not planned, a line each, until the user takes one up.

- **Enough addresses fill a listener.** A listener holds `limits.connections`, at most `limits.connections-per-address` of them from one counted address, so five counted addresses at the deployed 80 and 16 hold every place, each connection kept by a request within the idle deadline, and the next client waits in the backlog until one ends (design §7). Ending an idle connection for a newcomer was weighed and refused, since its kill frees the place while the host still sends its last response, for up to 3 minutes (the log's *Milestone 2, item 12: the caps by address*).
- **A C1 control character in the configuration reaches standard error.** Design §4's `hold no control character` refuses U+0000 to U+001F and U+007F, where the report's control characters run on through U+009F, and a refusal writes a value as `Json.encode` does, which writes U+0080 to U+009F bare; only a configuration written with one on purpose meets it.
- **A restart slower than the idle deadline closes with 1011.** A restart's attach waits for the session ending under its cookie, whose program has up to `shell.hangup` to exit, and a shell waits for its attach's answer within `timeouts.idle` (design §11, §12); so a configuration whose hangup comes near its idle deadline closes the restart of a program slow to exit with 1011, and the session then started is joined at the page's next attach. The deployed 5000 and 15000 milliseconds, and the example's 2000 and 60000, do not meet it.
- **A container whose wrapper is killed first runs until the unit stops.** A session whose reader or writer ends before its end kills its program without the hangup (design §12), and the wrapper's removal can fail; either leaves a container running within its caps and the slice, uncounted by `shell.most-at-once`, until the unit's `ExecStopPost` removes it at the server's stop (§13). Only a fault of the runtime's or of podman's meets it.
- **A wrapper killed before its end leaves an empty directory.** The wrapper's id directory under `/run/user/` and the user's number goes with its removal (design §13), so a wrapper killed before it, at the server's death, or hung up before its traps stand, in its first milliseconds, leaves the directory, emptied by podman's removal of the container, until the machine restarts. Only a server that dies, or a client that sends its stop with its first resize, meets it.
- **A file dated outside 1902 to 9999 is served with the bound as its time.** `Fs.stat` reads a modification time past 9999 as the last second of 9999 and one before 1902 as the first second of 1902, and design §5 writes that time as `Last-Modified` and compares it with `If-Modified-Since`; so two times past 9999 read as one, and a conditional request is answered 304 for a file changed between them. Only a file dated so on purpose meets it (language feedback line 60).
