# Ernest module ErnestHttpd

The program's entry point: the server started from its configuration
and stopped in order at the program's end (design §2).

`main` takes the configuration's path, the one argument, and reads the
file; a file that breaks a rule is refused with the field, the rule and
the value named, before anything listens. It then starts the access log and, where the
configuration has a `shell`, the sessions, and for each listener of the
configuration listens, over TLS with the certificate and the key for a
`tls` listener, says the port it got, and spawns the listener's process,
whose connections share the configuration, the site, the access log,
the sessions where there are any and, for the `redirect` listener, the
ACME challenge's site. At the program's end, a termination signal, it
stops the sessions first, which closes every shell with 1001 and ends
every session, and waits for them; then it tells each listener to stop,
waits for each to end its connections in order, has the access log
write what it holds, and lets the end go on.

The exit statuses are 2 for a command line of another count of
arguments, 1 for a configuration refused and a listen that fails, a
port below 1024 denied naming the capability it needs, and the signal's
at the end. A listener's process that ends before the end
is a failure: the entry process stops the sessions and the other
listeners, as at the end, says so on standard error, and exits with the
status 1.
