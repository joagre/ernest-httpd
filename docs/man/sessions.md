# Ernest module Sessions

The sessions: one process that holds every visitor's session by its
cookie, starts one within the caps, and ends them all at the program's
end (design §12).

A shell attaches with its cookie, `Attach`: a cookie that names a live
session is passed to it, and another starts a session of the page's
size where fewer than `most-at-once` live and the shell's remote address
has made fewer than `starts.count` starts within the last
`starts.within` milliseconds; otherwise the shell is told `Unavailable`.
A visitor is so counted by the remote address, which clearing a cookie
does not reset.

A session calls the sessions as its end begins, `SessionEnding`: its
cookie names it no more, so that an attach under that cookie starts a new
session, and the call is then answered, so that every attach passed to
the session before stands in its mailbox, told its end's code. The
session is counted among the live until it has ended or a session is
started under its cookie, which then counts in its place, so that a
visitor's restart never meets the cap.

`Stop` ends every session with 1001, which closes every shell attached,
and answers once each has ended; after it every attach is told
`Unavailable`.


What the sessions take: a shell's attach, with its cookie, its remote
address, the page's size and the shell's address; a session's call as
its end begins, and its end; and the request to stop, which the
program's end sends.
