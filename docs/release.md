# The release

What a release runs to be ready, and nothing else. Between releases a change runs `make test` before every commit (CLAUDE.md, *The work*).

1. **A fresh clone builds and passes**, as [`full_review.md`](full_review.md)'s *How it runs* has it.
2. **The readers** of [`full_review.md`](full_review.md), run as it runs them, with its briefs: for a release before the program is first recommended to others, K, the cold reader; from that release on, C, the code reader, beside it, over `src/`.
3. **The findings**, sorted and worked as [`full_review.md`](full_review.md)'s *The findings* says.
4. **The round:** once the findings are fixed, K again over the diff, from the commit the review started on to the release's commit, of what it reads: the lines the review's own fixes wrote there and no reader has read. The session reads the code's lines back as each agent returns them (CLAUDE.md, *Honest reports*).
5. **The note**, the release's section of `CHANGES.md`, first in the file and committed before the tag, which the release step copies as the notes of the release on GitHub so that it is written once: what the release is, naming no milestone, review or log entry, since its reader is a user; what a program or an operator of the previous release changes; the design's diff between the last release's tag and this one's; and one line a change naming the design's section where it is read. It restates no change, and its date stands in its heading alone.
6. **The release:** `VERSION` set; for a library, every exported declaration that appeared since the last release ending its doc block with its own `since`; the tag, signed, `git tag -s v<version>`, with an SSH key GitHub holds as a signing key, so that GitHub marks it verified; and the archive `make release` writes, `build/<name>-<version>.tar.gz`, published beside the tag with its checksum, `build/<name>-<version>.tar.gz.sha256`, so that another repository's `package.conf` can name it by its URL and its digest and a user can check it. The session runs the release to the tag and the archive; the push and the release on GitHub wait for the user's word (CLAUDE.md, *What is the user's*).
7. **`language_feedback.md`'s lines carried to Ernest**, as CLAUDE.md's *The work* says, so that a release leaves nothing the language has not heard.
