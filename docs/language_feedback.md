# Language feedback

What writing Ernest felt against the principles, a line each, a queue: a line is carried to Ernest's `language_feedback.md` by copy, the log here cites Ernest's number, and the line then goes. The file goes when it is empty. The lines are numbered here from 1; Ernest's shape is not in the installation, so each is reshaped as it is carried. Each was found on 2026-11-02 against Ernest 0.9.0, building the design's §4 and §5.

1. **`Fs` answers `Other` with the host's prose where a path leads to nothing.** `Fs.stat(Path("index.html/x"), ms)` answers `Left(Other("not a directory"))`, the host's ENOTDIR; a name of 300 characters `Other("file name too long")`; a loop of links `Other("too many levels of symbolic links")`. E.17 says `stat` answers what the path leads to, and each of these leads to nothing. A web server asked for `/index.html/x` has to answer 404, and can tell the case from a failure of the file system's only by reading the host's text, so `Static` answers 500 there, which a client can make it do at will. Principle 3: the failure's kind stands in prose alone. Ask: each of the three answers `Left(NotFound)`, in every function that follows a path, stated in E.17 beside `NotAFile`.

2. **`String`'s searches have no code-point form.** `split`, `splitOnce`, `startsWith`, `contains` and `indexOf` match by grapheme (E.5), while `Path` reads by code point (E.14). The code a reader writes for protocol text, `String.split(path, "/")` and `String.startsWith(target, "/")`, leaves `"/\u{301}"` unsplit, one grapheme; joined by `Path.join`, that segment is an absolute path, which `<>` answers whole, outside the root. `Static` splits by `Bytes.split` and reads `List(Char)` instead. Principle 1: a reader who knows Erlang predicts that `/` splits wherever it stands, and `Path.join` taking a segment that holds the separator with no refusal makes it worse.
3. **A last clause `<<>>` does not cover the empty `Bytes`.** A bitstring pattern counts as matching no value for coverage (§5.11), so a decoder over `<<37, high, low, rest:bytes>>`, `<<37, _:bytes>>` and `<<byte, rest:bytes>>` cannot end in `<<>> -> Some(acc)`; it ends in `_ -> Some(acc)` with a comment saying that `_` is the end of the bytes. Principle 1: the reader predicts `<<>>` as the base case, as Erlang writes it.
4. **E.1 does not say whether `Io.show` qualifies another module's constructor.** It writes `Header(name = ...)` and `Invalid(...)` unqualified, so a doc example's `// =>` line reads differently from the expression the program writes, `Http.Header`, `Config.Invalid`, and the writer finds that out by running it. The page is silent where shape rule 6 makes the writer depend on it.
