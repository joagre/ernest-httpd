# Decisions, 2026-10-27

## What the server leaves out

*2026-10-27.* A request's body is refused, 413, since nothing on the site takes input over HTTP, and with it chunked request decoding and `Expect: 100-continue`. No response is chunked, since every file has a size. There is no `Cache-Control`, since `Last-Modified` and 304 make a revisit a cheap check; headers by path wait for a measured need. A WebSocket negotiates no extension and no subprotocol, which the page asks for none of. Principle 5.

Compression waits until a first visit is measured slow. Its shape is known and changes nothing of the server: the site's generator writes `page.html.gz` beside `page.html`, and the server sends it where `Accept-Encoding` names `gzip`, with `Content-Encoding: gzip` and `Vary: Accept-Encoding`, compressing nothing itself. There is no rate limit on requests: a static file is cheap, the shells have their caps and their start limit, and a flood past these is the network's to stop. At the connection cap the excess waits at the kernel, and no 503 is answered, which would spend work on the clients there are too many of.


## What the server takes from a client

*2026-10-27.* The path is decoded before its check, so that `/%2e%2e/` is refused as `/../` is. `%2F` is refused, since no name on the site holds one. A name beginning with `.` answers 404, so that nothing like a `.git` or an editor's backup is ever served. Two `Host` headers or a folded header answer 400, and with bodies refused, request smuggling has nothing else to work with. A redirect is built from the configured host alone, so that a forged `Host` cannot make the server a redirector to anywhere. `Origin` is checked, since a WebSocket is not held to the browser's same-origin rule. Principle 1.


## The session's shape

*2026-10-27.* A session outlives its connection, since moving to another page closes the WebSocket and the site keeps a visitor's shell across pages. It starts at the page's first resize, so that the shell starts at the panel's size and not at a guessed one. Its lifetime is five minutes from the last key or Extend, one deadline that either moves. It replaced an idle time with a key's answer and a total of 30 minutes: Extend serves a visitor whose program runs without typing, and there is no total cap, since a session kept alive holds one of the shells the cap allows and no more (principle 5). Starts are counted by remote address and not by cookie, which a visitor resets by clearing it. The cookie is set on the 101 alone, so that the static pages set none and the privacy line can say that the shell alone does; it is drawn from `Crypto.randomBytes`, so it cannot be guessed.
