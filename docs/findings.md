# Findings

The cold reading of the shell client's design sentences, `docs/design.md` §3, §13, §14 and the glossary as commit c1814c5 left them: its six findings of naming and register, which a design session decides with the user, as the plan's *The proposal's reading and sweep* says. Its ten that misstated what is built are fixed.

- **The glossary's *client*.** It names the module served at `shell.client`, where §6, §8, §10, the glossary's *target* and *connection* and the tests' helpers use the word for a request's sender, the report's word. The reading's suggestion: the entry states both, "a request's client, §6, §8 and §10, is the report's word for its sender".
- **§14's *session* for the page's object.** `start` "answers the Session at once", and `Session.keys` and the prose's "what the session is asked" name the object the page holds, where the glossary's *session* is the process, §12. The reading's suggestion: *handle* for the object, in the glossary if it recurs.
- **"The interface below is the one thing the server and the site it serves share."** §13 has the site know the client's path too, so the sentence is false as written. The reading's suggestion: delete it.
- **Three sentences of rationale in §14.** "A browser keeps no copy, so a page loaded whole runs the client of the server it talks to; ... a reload mends it"; the test's headers' "which would refuse the page's report"; and "so a stop asked before the attach is ordered after the size, and the shell holds it until the session is attached", which also restates §11's hold. The reading's suggestion: each to the log, §14 keeping the rule.
- **"`chromium` on `PATH`, which `make test` needs".** How the program is tested is the README's, which says it. The reading's suggestion: drop the clause.
- **"held as written in a raw string" and "holds no backtick".** The form `Client.text` is built in, not a rule of the client. The reading's suggestion: drop both, keeping "defines nothing on window", which a test checks.
